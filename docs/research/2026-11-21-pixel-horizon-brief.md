# 《极速竞技·地平线》首轮研究

日期：2026-11-21。项目目录：`Pixel_Horizon`。本文件是研究建议，供确定制作方向；当前尚未实现游戏。

用户后续明确：任务较少，需要更丰富的场景，主要乐趣是开车看风景、放松。以下范围已按这个定位调整。

## 推荐：真 3D 像素公路旅行，以风景与轻松驾驶为中心

沿用 KongZhan 的像素画风与空间感，制作一款打开即可驾驶的轻量赛车游戏。默认车参考用户图片中的红色 Mercedes-AMG ONE；首版提供一张有六段鲜明风景、自然过渡和观景支路的山海地图，以及四种驾驶视角。默认进入自由驾驶，短程竞速作为自选活动。

选择内容的标准是：是否让玩家愿意继续看下一个弯后的风景，或停下来欣赏当前景色。首版优先投入沿途景观、地形与道路构图、舒适相机、可控驾驶和车辆辨识度。抓地、侧滑与速度反馈服务于轻松驾驶；任务链、车辆收集、改装经济系统、联网以及庞大开放世界留在首版之外。

## 现有项目提供了哪些依据

- `Pixel_Horizon` 在本轮开始时为空，适合建立独立的赛车工程。
- 参考项目 `KongZhan` 当前检出 `feature/reference-pixel-world`，有未提交变更。本轮仅以其当前工作区和已有截图为只读参考。
- KongZhan 使用原生 JavaScript 与 WebGL2，是真 3D 渲染。地形采用高度场光线步进，实体使用低多边形网格、分面法线和分档光照。
- 像素观感来自较低的世界渲染分辨率、最近邻放大和每通道 32 级色阶；UI 单独以清晰分辨率绘制。
- 参考图像中的暖色地平线、蓝灰天空、紫褐山体、秋林色块和清晰物体轮廓，适合红色跑车与山海公路。
- 现有地形是 8192 米周期世界、1024×1024 高度场，每格约 8 米。该尺度适合飞行观景，赛车道路、路肩和轮胎接触需要另行设计。

## 首版范围：一辆车、一张丰富地图，自由驾驶优先

| 内容 | 建议 |
| --- | --- |
| 默认车辆 | 红色 AMG ONE 风格低多边形超跑，配黑色车顶、暗色前舱盖和大尾翼 |
| 地图 | 连贯的山海公路环线，舒适巡航一圈以约 8–12 分钟为设计目标；有六段风景和少量观景支路，实际时长待原型测定 |
| 自由驾驶，默认 | 可慢开、快开、停车、环视与切换视角；没有强制倒计时或排名。草地降低抓地并产生尘土反馈 |
| 观景探索 | 海边停车点、湖畔支路、山顶观景台等可自由抵达的地点，通过路牌与可见地标引导 |
| 可选短程比赛 | 选择主路线中的一段与三辆电脑车比赛，提供检查点、名次、用时和重开；在自由驾驶与风景体验成立后制作 |
| 操作 | WASD 或方向键驾驶，空格手刹，C 切换视角，R 回到道路，Esc 暂停；自动换挡 |
| HUD | 自由驾驶时显示时速与可收起的路线图，支持隐藏界面看景；比赛时显示进度、名次、用时 |

道路要兼顾驾驶与观景：明确的路边界、足够的前方视野、宽缓弯道和适量长直道，让玩家能稳定驾驶并看清景物。容易冲出道路的位置提供明确提示和宽容的恢复空间。发卡弯集中在山路段，开阔路段给予更舒缓的节奏。

默认按桌面浏览器和键盘操作提出方案。触屏、手柄、移动端性能下限尚未确定，不以已支持处理。

## 六段风景连成一次完整旅行

| 路段 | 主要画面与路边细节 | 驾驶与观景节奏 |
| --- | --- | --- |
| 海湾小镇 | 彩色房屋、码头、停泊小船、沿街树木和海边停车点 | 平缓起步，先看到远处灯塔与海岸线 |
| 滨海悬崖 | 碧蓝海面、礁石、白色灯塔、沿崖护栏，海湾小镇退入远景 | 宽阔海景与缓弯交替，留一处能停车看海的平台 |
| 金色田野 | 麦田、花田、风车、农舍和远山 | 长直道舒展视野，路边细节形成清楚的近景速度感 |
| 秋色河谷 | 金红树林、流动河道、石桥和跨河公路 | 林荫遮蔽与桥头开阔交替，沿河逐步上行 |
| 林间湖泊 | 湖面、瀑布、松林、木屋和湖畔短支路 | 放缓节奏，可驶到水边停车，听水声和鸟鸣 |
| 高山垭口 | 山脊公路、紫灰远山、谷中薄雾和开阔观景台 | 少量发卡弯后展开全景，经舒缓下山段回到海湾 |

这些区域通过海拔、水系和植被渐变连接。让同一座远山、同一条河以及出发时的海湾从不同路段再次出现，帮助玩家建立空间感。转弯后的视野展开、开阔与林荫交替、桥梁和隧道出口的明暗变化，共同构成沿途节奏。

场景丰富度依靠独特构图和可记住的地点。优先打磨灯塔、河谷石桥、湖畔与山顶四处观景节点，再用植物、岩石和道路设施的组合填充途中。近处有路肩、草丛与落叶，中景有树木、房屋和水面，远景有山脊、海湾与云层。

第一版先提供晴日与暖色傍晚两套光照氛围；低日照、分层薄雾和天空渐变继承参考项目的色彩方向。海浪、风声、鸟鸣与溪水随区域变化，音乐可关闭。相机起伏与屏幕震动保持克制，停车后可环视、隐藏 UI 看景。

主要范围风险是更长道路上的重复景观。制作时先确定道路与观景节点的视线关系，集中建设实际可见的沿路区域；在悠闲驾驶下检查重复感，再决定支路数量和最终路程。动态天气和完整昼夜循环暂列后续扩展。

## 四个视角共享同一辆车和同一套驾驶状态

| 视角 | 作用与设计重点 |
| --- | --- |
| 追尾，默认 | 看清车身与下一段道路；相机跟随航向，转弯时保留适量观察提前量 |
| 引擎盖 | 更直接地感受道路和车速，车身运动只产生适量起伏 |
| 驾驶舱 | 有方向盘、仪表台和 A 柱；前方道路保持可见，镜头避免跟随每一次细碎震动 |
| 高位追踪 | 更容易观察路线、海岸线与周边地形，适合轻松驾驶和看风景 |

切换视角不能重置速度、位置或比赛状态。追尾相机要处理山体、护栏和树木遮挡。世界采用像素渲染时，速度数字与路线提示仍保持清晰。

## AMG ONE：先把轮廓做好，再加小细节

车型辨识主要依靠低矮宽体、短而下压的车头、水滴形座舱、车顶进气口、细长前灯、大进气口、大尾翼和大轮圈。首版模型应优先保证这些比例，从正前、侧面和后方都能认出参考车。

推荐制作原创的程序化低多边形模型，使用红色车漆与深色碳纤维区域分色。车身、四个轮子、前轮转向节点、方向盘和相机挂点独立组织，以支持车轮滚动、转向和驾驶舱视角。前轮采用“转向枢轴 → 滚动轮组”结构，车辆运动与碰撞尺寸独立于视觉网格。驾驶舱需要有实际几何结构，不能仅把相机移进空车壳。

glTF/GLB 适合作为后续精细模型的载体，但目前没有确认可直接使用、许可清楚且满足轮子拆分和内饰要求的 AMG ONE 文件。研究建议不把这类下载模型设为首版依赖。程序化低模也更容易与参考项目的画风保持一致。

## 技术路线：推荐 Three.js 与轻量驾驶模型

| 方案 | 优点 | 主要代价 | 判断 |
| --- | --- | --- | --- |
| 2D 或伪 3D 公路 | 固定赛道容易快速出效果 | 自由探索、驾驶舱、坡道与连续视角切换会受限 | 不适合当前核心要求 |
| 延续 KongZhan 自研 WebGL2 渲染器 | 能直接沿用部分像素后期思路 | 仍需重做道路接触、车辆和镜头；增加底层渲染维护 | 适合有明确共享引擎目标时再考虑 |
| Three.js 真 3D | 相机、网格、材质、实例化与 glTF 加载成熟 | 增加渲染依赖，需要自行统一像素画风 | 首选 |

建议使用轻量 JavaScript 模块组织逻辑，Three.js 负责场景与渲染，Vite 负责开发和打包。道路使用连续曲线生成网格，并提供统一的道路高度、方向与路面查询，供车辆、电脑对手、检查点和重置位置使用。

驾驶采用固定物理步长，以简化的抓地与侧滑模型提供加速、制动、随速度变化的转向、手刹漂移和草地减速。车身俯仰、侧倾、轮子转动、胎烟和音效表达状态。是否需要引入 Rapier 等通用物理库，应由具体碰撞和跳跃需求决定；首版不预设完整刚体车辆模拟。

电脑对手仅在自选比赛中加入，沿同一条道路路线行驶，根据弯曲程度调整目标速度，并使用轻量避让。自由驾驶不要求比赛参与。像素后期、实例化植被、距离裁剪和世界/UI 分辨率分离可沿用参考项目的思想。

性能以桌面浏览器稳定 60 FPS 为目标，待原型测量。画面内部尺寸、植被数量和阴影预算根据实际场景调节；本轮没有足够依据承诺移动端帧率。

## 制作顺序与验收重点

1. 先制作一段能实际开车观景的代表路段，包含海岸开阔景、林荫过渡和观景停车点；让默认车辆完成基本驾驶与回路重置，并接通四个视角。
2. 验证车辆比例、相机舒适度和沿途构图后，扩展六段风景与主环线，加入少量观景支路、两套光照和分区环境声，完成像素后期。
3. 调整抓地、侧滑、轮胎与引擎反馈；自由驾驶达到观景质量后再加入短程比赛、三个电脑对手、检查点、结果和重开。

驾驶原型的决定性证据是：低速能控制、高速能入弯、手刹能形成可恢复的侧滑、掉出道路能回到正确方向；不同刷新率下的速度与转向保持一致。视觉验收应实际查看四个视角、直道与弯道，确认 AMG ONE 轮廓、前方视野和像素可读性。

观景验收需要以悠闲车速完整走一遍主路线，确认六段景色有明确区别、过渡自然、远景地标连贯；四处重点景观有适合停车的视角，支路能正常返回。自由驾驶应可一直游览，隐藏 HUD 后仍可正常控制车辆。相机在弯道、坡道与车内视角下应舒适，环境声与景观区域相符。比赛验收另覆盖漏过检查点、超车、完成比赛和重新开始。

下一阶段先确认这份首版范围，再形成实施计划。当前工程仅新增研究文档，赛车代码、可玩版本和性能证据尚未产生。
