# Agent Note: 可行驶路网的支线与共享路口

Status: implemented

## Problem

首版只有一条 7.46 km 的封闭环线，跑完一圈后路线选择单一，山体内部的大片地形也没有可到达的道路。需求是把路网扩充到接近开放世界驾驶游戏的数量与形态：长环线、短支线、捷径、S 弯和高低差都要有，主路与支路、支路与支路之间允许交叉或汇合；同时每个路段必须真正可驾驶，不能悬空、穿模或出现高度台阶。扩充还不能破坏既有契约：驾驶、相机、区域、比赛和地图都只认识 `road.sample` / `road.nearest` / `road.groundHeight`，小地图与导航 UI 由另一条工作流维护。

## Decision

路网以数据驱动方式定义在 `src/world/route.js` 的 `BRANCH_DEFS` 中：主线仍是原来 21 个控制点、7458.6 m 的封闭 Catmull-Rom 环线；另外新增 7 条支线，共 6647 m。支线用稳定 id 1–7 标识，类型分 `secondary`（宽 9.4 m）与 `trail`（宽 7.4 m），分别对应次级公路和碎石林道。支线端点可以锚定在主线的 `startT` / `endT` 上，也可以落在共享内部节点 `V0`、`V1`、`V2`、`V3`、`V5` 上；9 处主线岔口与 5 个内部路口共同组成约 14.1 km 的连通路网。

道路 API 保持主线旧接口不变，同时增加按路线取样的 `sampleOn`、`lengthOf`、`widthOf`、`kindOf`、`isClosed`、`nameOf`，并让 `nearest(x, z, preferredRoute)` 返回 `route` 与 `width`。驾驶状态新增 `route`，每帧通过带偏好的最近点查询更新；`mainT` 始终记录最近的主线参数，区域判断、比赛和 HUD 继续消费它。这样地图、区域和比赛不需要知道支线的存在，只有驾驶、相机和巡航改为按当前路线取样。

支线几何用与主线相同的 centripetal Catmull-Rom 采样，间距 3 m。每个主线岔口在需要时插入 38 m 的过渡引导点，把支线方向与主线切向混合，避免出现 4–10 m 半径的掉头弯；实测所有支线最小转弯半径不低于 37 m。

高程分两遍求解，避免道路高度与地形高度互相依赖。第一遍用原始地形高度计算共享节点的统一高程，再为每条支线做“平滑地形—锚点吸附—15% 坡度夹紧”的纵断面；锚点在每次正反向夹紧时都保持固定，所以汇合点不会出现台阶。第二遍地形在 `baseHeight` 之上按支线距离切削路廊，并生成逐支线的细节地形带。主线与支线在平面上会重叠约 50 m，若只锚定单个端点，支线可能比主线高出 1.3 m，形成浮空路和切路时的垂直跳变；因此支线在距主线中心线 `mainWidth / 2 + 1.9 m` 以内直接跟随主线纵断面，再在 10 m 内过渡回自身剖面。共享内部节点则设置 ±14 m 的平坦台地并固定到节点高程，向外 20 m 过渡，使两条支线在整段重叠宽度内都贴合，而不只是在一个采样点等高。

路线选择采用“当前路线优先”的滞回规则：只有车辆离开当前路面的 `width * 0.55` 走廊，且另一条路明显更近时，才切换 `route`；开放支线到达端头时允许并入主线。这样主环线的观光巡航经过岔口时不会被吸到支线上，而从主线主动驶向支线的车辆仍能自然切换。

视觉上，次级公路与碎石林道使用不同宽度、材质和颜色；支线标线在两端各裁掉 34 m，避免画到主线路面上。所有支线的沥青、路肩、标线和碎石面分别合并为 4 个 `BufferGeometry`，路口细节地形也合并为 1 个网格，因此新增路网只增加 5 个 draw call。护栏、路灯、长椅、树木、石块、麦田和建筑按 `branchDistance` 或 `mainJunctions` 让出岔口和路廊。

小地图工作流所需的底图数据通过 `world.mapPaths` 与 `world.mainJunctions` 暴露；`src/ui.js` 没有改动，仍由导航工作流负责绘制与高亮。

## Alternatives considered

- **多条独立闭环，各自一套样条与地形**：能最快增加路线数量，但会让区域、比赛和地图各自维护多套参数化，地形切削也会重复计算。最终选择共享主环线与内部节点的单一路网。
- **只按地形高度铺支线，不做显式路口节点**：实现简单，但两条支线汇合处的高程只能碰巧一致，实测会出现米级台阶。最终为每个共享节点先定统一高程，再分别放坡。
- **支线高程只锚定端点**：这是最小改动，但支线与主线并行的 50 m 内会高出主线 1.3 m，车辆切路时会瞬移，视觉上也是一条浮空带。最终增加跟主线纵断面的路口裙边与共享节点台地。
- **在主线路口做水平裙边（固定端点高度）**：当主线本身有纵坡时，裙边末端仍会与主线分离。最终让裙边跟随主线的纵向高程，再过渡回支线剖面。
- **不带偏好的最近路查询**：巡航经过岔口时会被更近的支线中心线吸走，现有环线巡航测试直接失败。最终保留当前路线优先和离开走廊才切换的规则。
- **每条支线单独建网格**：路口细节更直观，但 7 条支线会增加 14 个以上的 draw call。最终按材质合并。
- **直接修改 `src/ui.js` 画支线**：能立即在小地图看到新路，但该文件属于导航工作流，任务约束明确禁止改动。最终只暴露 `mapPaths` / `mainJunctions`，由导航工作流消费。

## Consequences

路网从 7.46 km 增至 14.1 km，支线覆盖东谷、中央横断、南鞍与西岭等原先无法到达的区域；主线长度、参数化和六个区域的位置完全不变，因此旧存档式的 `t`、比赛路段与区域判断继续有效。新增高程逻辑使创建世界时多一次支线最近点查询和一次地形细节带生成；浏览器实测仍为 60 fps，场景约 727 draw calls、154 万三角形，其中支线部分为 5 draw calls、7.2 万三角形。独立 HTML 从 1,352,777 字节增至 1,364,276 字节（+0.85%）。

`tests/network.test.js` 覆盖支线数量与长度、逐样本最近点与地面高度、端点/共享节点高差、最小半径、最大坡度、水面避让、路口重叠高程、每条支线的无人巡航以及汇入主线；`npm test` 共 22 项通过。构建、车辆检查与浏览器验收（`verify:browser`、`verify:cruise`、`verify:instruments`、`verify:garage`、`verify:memory`、`verify:standalone`）均通过。

已知边界：观光巡航只沿当前路线的参数增大方向前进。支线 2 与支线 5 都把终点落在 `V3`，从其中一条支线开启巡航走到端头后没有顺向的下一段路，需要手动转向；主线环线巡航与从支线汇入主线的行为不受影响。小地图底图尚未接入 `mapPaths`，这是导航工作流的后续集成项。路人车辆仍由交通工作流负责，本变更不涉及。
