# Agent Note: 观景驾驶的状态与几何边界

Status: implemented

## Problem

玩家希望没有任务压力也愿意继续开车，因此场景、多视角与驾驶手感比复杂赛制更重要。飞行参考项目的粗高度场无法直接承担当车辆与道路接触的依据；外部模型的内饰、车轮节点与可用许可也未得到验证。

## Decision

本项目采用 Three.js 真 3D、程序化车辆和山海场景。道路是位置、高度、航向与路段进度的唯一几何依据：world 提供 `sample`、`nearest` 与 `groundHeight`，驾驶、相机、地图和电脑对手消费同一条道路。

`drive.js` 以 1/120 秒固定步长更新车辆状态；`car.js` 只负责模型与轮子、方向盘、车身反馈，不能改 root 的位置和航向。`camera.js` 只消费车辆状态与道路，四视角切换不会重置行驶。`main.js` 持有输入、屏幕与比赛状态，恢复驾驶时统一退出摄影；`ui.js` 只呈现状态和发出动作。

自由驾驶默认没有比赛压力，巡航可被手动驾驶接管。场景以约 7.46 km 连续环线串联六个区域，地图允许直接抵达，短程比赛从地图入口自选。世界低分辨率渲染与 DOM HUD 分离；植被与建筑实例化。声音与模型不依赖外部下载。

Vite 输出网站，打包工具把生成的脚本、样式、字体与许可嵌入独立 HTML，保留直接双击的试玩入口。源模块仍独立维护，独立 HTML 是构建产物。

## Alternatives considered

- 2D / 伪 3D 公路实现固定线路较快，但难以满足驾驶舱、自由停车环视和连续地形，未采用。
- 延续 KongZhan 自研 WebGL2 可以共享部分像素后期，但需要重写地面道路、接触和相机，增加底层渲染维护；本项目只沿用美术思想。
- 外部 glTF AMG ONE 可能提供更精细外观，但可用许可、内饰和节点均未验证，首版采用原创低多边形造型。
- 通用刚体车辆物理适合碰撞与腾空模拟，但当前驾驶目标以舒适巡航为主；首版采用简化抓地与侧滑模型。

## Consequences

道路、车辆视觉与驾驶状态有清楚边界，修改画风或车模不会重新定义驾驶规则。程序化景观需要逐处检查实际相机下的构图，投影可见与数值正确不能替代浏览器目视；首轮检查实际发现了车壳法线、挡景建筑和过近远山。

`npm test` 覆盖加速、制动、转向、重置、巡航接管和完整环线；`tools/verify-playable.mjs` 覆盖真实键盘、四视角、摄影恢复、六景区、日光、暂停、完整短赛与触控。性能证据限于当前 Chrome 验收环境，不能外推为所有移动设备的保证。

## Notes audit

本项目初始没有 `.agents/notes/` 或既有架构决定。研究简报为需求来源，实施计划为本次文件归属依据，本篇记录实际采用的模块边界与取舍；不建立第二份重复 ADR。
